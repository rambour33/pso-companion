Le principe

Le Stream Deck ne sait rien faire tout seul. Chaque touche est configurée dans Companion, qui envoie un ordre au bon logiciel au moment où tu appuies. Le skill companion fabrique ces touches à ta place, pour n'importe quel projet.

Stream DeckUn XL a 32 touches (8 × 4) par page. ⬆️ ⬇️ changent de page.
CompanionContient la config des touches (fichier .companionconfig) et des connexions : une generic-http par projet, vmix si besoin.
Ton projetN'importe quel logiciel qui expose une API HTTP : serveur Node, Python, outil maison…HTTP GET / POST → http://hôte:port/api/…
vMixPreview, program, transitions, stingers, overlays, REC, stream, replay, audio.TCP → 127.0.0.1:8099

Tu décris les touches voulues dans une spec (un petit fichier JSON, ou simplement en français à Claude). Le script du skill la transforme en fichier Companion, que tu importes. Companion peut aussi lire l'état de vMix : une touche s'allume en vert quand son input est en preview, en rouge quand il est à l'antenne. C'est un feedback.

Les fichiers

Le dépôt P:\pso-companion (aussi sur GitHub) est la version de référence. Chaque skill y a son dossier dans skills\. Installé, le skill vit dans %USERPROFILE%\.claude\skills\companion (tous les projets) ou <projet>\.claude\skills\companion (un seul projet).

Serveur de skills

Un petit serveur local met les skills et cette documentation à disposition de tous les PC du réseau.

AdresseContenu
http://<IP>:3011/Catalogue : chaque skill avec son .zip, sa commande d'installation et la lecture de ses fichiers. Liste aussi les exports Companion des dossiers déclarés dans config.json.
http://<IP>:3011/docsCette documentation.
/download/skills/companion.zipLe skill companion, prêt à décompresser dans %USERPROFILE%\.claude\skills.
/api/skillsLa liste des skills en JSON.

Lancer le serveur

Double-clique sur P:\pso-companion\start.bat. Au premier lancement il installe ses dépendances, puis ouvre le catalogue. La fenêtre affiche les adresses à utiliser depuis les autres PC :

📦 pso-companion démarré !

  ── Ce PC (localhost) ──────────────────────────────────────
   Skills     → http://localhost:3011/
   Doc        → http://localhost:3011/docs

  ── Autre PC (réseau local) ────────────────────────────────
   Skills     → http://192.168.1.x:3011/

Ajouter un skill

Crée un dossier dans P:\pso-companion\skills\ avec un SKILL.md dont l'en-tête contient name: et description:. Il apparaît dans le catalogue au prochain rechargement de la page, sans redémarrer le serveur.

Le serveur est en lecture seule mais sans mot de passe : tout PC du réseau local peut télécharger les skills et les exports Companion. Ne le laisse pas tourner sur un réseau public.

Si Windows demande l'autorisation du pare-feu au premier lancement, autorise les réseaux privés, sinon les autres PC ne pourront pas l'ouvrir.

Mise en place

Pour un nouveau projet. Coche chaque étape quand elle est faite : ta progression reste enregistrée dans ce navigateur.

0 / 8

  1. Vérifier les logiciels

    • Companion 4.3 ou plus récent.
    • Python 3 : tape python --version dans un terminal.
    • Claude Code, pour demander les touches en français.
    • Si ton projet utilise vMix : vMix ouvert, port TCP 8099 libre (le Web Controller de vMix ne doit pas utiliser ce port).

  2. Installer le skill

    Ouvre le catalogue http://<IP>:3011/ et copie la commande d'installation, ou tape directement (remplace l'IP). Le skill est alors disponible dans tous tes projets :

    Invoke-WebRequest http://192.168.1.x:3011/download/skills/companion.zip -OutFile "$env:TEMP\companion.zip"
Expand-Archive "$env:TEMP\companion.zip" -DestinationPath "$env:USERPROFILE\.claude\skills" -Force

    Vérification : dans Claude Code, tape /companion. Le skill doit se charger.

  3. Repérer l'API de ton projet

    Companion appelle des adresses web. Il faut savoir lesquelles :

    • l'adresse de base du projet : http://localhost:8080, ou l'IP du PC qui le fait tourner ;
    • les routes à déclencher : /api/banner/on, /api/timer… et leur méthode (GET, POST…).

    Si le projet est ouvert dans Claude Code, Claude les trouve lui-même en lisant le code du serveur. Sinon, garde la liste sous la main.

    Pas encore d'API ? Demande à Claude d'ajouter au serveur de ton projet des routes simples, par exemple GET /api/deck/<élément>/show et /hide, comme dans l'exemple PSO.

  4. Partir d'un fichier Companion

    Companion déjà configuré : exporte ta config (Companion → Import / Export → Export) et garde le fichier. Pour voir ce qu'il contient :

    python "$env:USERPROFILE\.claude\skills\companion\scripts\companion.py" dump "D:\MonProjet\export.companionconfig"

    Projet neuf : crée un fichier vide.

    python "$env:USERPROFILE\.claude\skills\companion\scripts\companion.py" init "D:\MonProjet\companion.companionconfig"

  5. Décrire les touches

    Le plus simple : demande à Claude, dans le projet. Par exemple : « Fais-moi une page Stream Deck avec un toggle pour le bandeau (/api/banner/on et off), un bouton recharger, et un bouton INTRO qui cache le bandeau, lance l'intro et le remet après 8 s ».

    Claude écrit la spec, génère le fichier et te dit quoi importer. Pour écrire la spec toi-même, voir Écrire une spec.

  6. Générer le fichier

    Si tu as écrit la spec toi-même :

    python "$env:USERPROFILE\.claude\skills\companion\scripts\companion.py" apply "D:\MonProjet\companion.companionconfig" "D:\MonProjet\ma-spec.json" --out "D:\MonProjet\companion-nouveau.companionconfig"

    Avec --out, le fichier d'origine n'est jamais modifié. Ajoute --dry-run pour vérifier sans rien écrire.

  7. Importer dans Companion

    • Companion → onglet Import / Export → importe le fichier généré.
    • Choisis seulement les pages et les connexions concernées.
    • Si Companion propose d'installer un module (generic-http, studiocoast-vmix), accepte.
    N'importe jamais en « tout remplacer ». Companion recrée alors l'intégration Stream Deck pendant que le deck est ouvert, et le deck peut rester noir (voir Dépannage).

  8. Vérifier et tester

    • Onglet Connections : chaque connexion doit être au vert. Une connexion HTTP en erreur veut dire que le projet ne tourne pas ou que l'adresse de base est fausse.
    • Appuie sur une touche simple (un GET) et vérifie l'effet dans ton projet.
    • Teste les enchaînements hors direct. Ne teste pas les touches qui lancent ou coupent un stream.

Exemple : régie PSO

Un projet réel qui montre toute la démarche : un serveur Node (port 3002) pilote des overlays de tournoi Smash Bros, et le Stream Deck le contrôle en même temps que vMix. Les fichiers sont dans examples/pso/.

1. L'API du projet

Le serveur expose des routes GET faites pour le Stream Deck :

RouteEffet
/api/deck/<overlay>/show · /hideAffiche / cache un overlay (scoreboard, casters, cam, victory…)
/api/deck/score/p1/inc · p2/dec…Score ±1
/api/deck/score/resetScore 0-0

2. La connexion

Les specs déclarent "http": { "label": "http", "base_url": "http://localhost:3002" }. Les touches utilisent donc des adresses courtes comme /api/deck/cam/show.

3. Les deux specs

  • pso-overlays.json : barre de score, 21 toggles d'overlay (on_url = /show, off_url = /hide), et un bouton maître qui les commande tous.
  • pso-vmix-auto.json : des automatisations qui enchaînent l'API PSO et vMix. Par exemple DÉBUT MATCH : score à 0, écran VS 5 s, stinger vMix vers l'input JEU, puis scoreboard.

4. Les conventions propres à ce projet

  • Inputs vMix nommés JEU, CASTERS, PAUSE, MUSIQUE, MICROS. Les automatisations les appellent par leur nom.
  • Stinger 1 configuré dans vMix pour les changements de plan.
  • Les overlays valides sont ceux de la liste TRANSITION_IDS du serveur. Un autre nom renvoie une erreur 404, d'où l'importance de relire les routes avant d'écrire une spec.

Pour transposer à ton projet : remplace l'adresse de base et les routes par celles de ton API, garde la structure.

Types de touches

Chaque touche appartient à l'une de ces familles. Le nom entre parenthèses est celui qu'on écrit dans une spec.

Commande simple (get)

Un appui = une ou plusieurs requêtes GET vers ton projet. Exemple : recharger, +1 au score.

Toggle (toggle)

Deux états. 1er appui : actions ON, la touche passe au vert foncé. 2e appui : actions OFF, elle passe au rouge. Les actions peuvent être des GET, des POST, du vMix…

Bouton maître (master)

Active ou désactive d'un coup tous les toggles d'une liste, recolore leurs touches et les remet dans le bon état.

Macro (macro)

Touche libre : requêtes HTTP, actions vMix et pauses, exécutées l'une après l'autre. Peut avoir plusieurs états (steps).

Feedback

Couleur qui suit l'état réel de vMix : input en preview ou à l'antenne, REC, stream, mute. Il se met à jour tout seul.

Navigation (page_up, page_down)

Changent de page sur le deck. Par convention en haut à gauche de chaque page.

Écrire une spec

Avec Claude (le plus simple)

Dans Claude Code, ouvert sur ton projet, décris ce que tu veux en français. Le skill se charge tout seul, lit les routes de ton projet et fabrique le fichier. Exemples :

  • Crée une page Stream Deck pour piloter l'API de ce projet : un toggle par élément affichable et un bouton maître.
  • Ajoute un bouton qui lance le stinger 2 dans vMix puis appelle /api/casters/show.
  • Fais-moi un pupitre vMix pour les inputs 1 à 8 avec le tally.
  • Transforme ma touche « Minuteur » en toggle qui envoie un POST start / stop.

À la main

Une spec est un fichier JSON : la connexion, les pages, puis la liste des touches.

{
  "http":  { "label": "mon-app", "base_url": "http://localhost:8080" },
  "pages": { "1": { "name": "Mon projet" } },
  "buttons": [
    { "loc": "1/0/0", "kind": "page_up" },
    { "loc": "1/0/2", "kind": "get", "text": "Recharger", "url": "/api/reload" },
    { "loc": "1/1/0", "kind": "toggle", "text": "▶ Bandeau",
      "on_url": "/api/banner/on", "off_url": "/api/banner/off" },
    { "loc": "1/1/2", "kind": "toggle", "text": "▶ Minuteur",
      "on":  [ { "post": "/api/timer", "body": { "action": "start" } } ],
      "off": [ { "post": "/api/timer", "body": { "action": "stop" } } ] },
    { "loc": "1/2/0", "kind": "macro", "text": "▶ INTRO", "bg": "#006600",
      "actions": [ { "get": "/api/banner/off" }, { "get": "/api/intro/play" },
                   { "wait": 8000 }, { "get": "/api/banner/on" } ] }
  ]
}

vmixOptionnel : host et port de vMix, si la spec contient des actions vMix.
locEmplacement page/ligne/colonne. Lignes 0 à 3, colonnes 0 à 7 sur un XL. 1/2/0 = page 1, 3e ligne, 1re touche.
textTexte de la touche. \n = retour à la ligne. $(vmix:input_1_name) affiche le nom de l'input 1.

{ "post": …, "body": {…} }Requête POST avec un corps JSON (idem put, patch, delete).
{ "vmix": … }Action vMix. Les options non écrites prennent leur valeur par défaut (voir la référence vMix).

Dépannage

Le Stream Deck est reconnu, les touches marchent, mais rien ne s'affiche

Cela arrive après un import complet en « tout remplacer » : Companion a recréé l'intégration Stream Deck pendant que le deck était ouvert. Les journaux de Companion affichent Cannot write to hid device.

  • Quitte complètement Companion (clic droit sur son icône près de l'horloge → Quitter).
  • Débranche le Stream Deck 10 secondes, rebranche-le (de préférence directement sur le PC).
  • Relance Companion. À l'avenir, importe seulement les pages et connexions utiles.
Une touche HTTP ne fait rien
  • Ton projet doit tourner. Test : ouvre l'adresse de la route dans un navigateur (pour un GET).
  • Onglet Connections de Companion : la connexion HTTP doit être au vert et sa Base URL correcte.
  • Vérifie la route dans le code du projet : une route inexistante renvoie une erreur 404.
Une touche vMix ne fait rien
  • La connexion vmix doit être au vert : vMix ouvert, bonne adresse, port 8099.
  • Si la touche utilise un nom d'input, vérifie que l'input porte exactement ce nom dans vMix.
  • Les touches stinger demandent un stinger configuré dans vMix.
Des touches n'apparaissent pas sur le deck

Elles sont sans doute rangées hors de la grille (une 5e ligne sur un XL qui n'en a que 4). La commande dump les signale avec « hors de la grille ». Déplace-les ou ajoute des entrées empty pour les retirer.

Les pauses d'un enchaînement ne sont pas respectées

Les actions doivent être dans un groupe séquentiel. Avec une macro générée par le script c'est automatique. Si tu recrées la touche à la main dans Companion, place les actions dans un Action Group en mode Sequential.

J'ai modifié la spec mais le Stream Deck n'a pas changé

Il faut régénérer le fichier puis le réimporter dans Companion. Companion ne surveille pas le fichier.

Les touches vMix n'affichent pas le nom des inputs

La connexion vMix doit s'appeler exactement vmix dans Companion : c'est ce nom qui apparaît dans $(vmix:input_1_name).

Le serveur de skills ne démarre pas : « port déjà utilisé »

Il tourne déjà dans une autre fenêtre : ouvre http://localhost:3011/. Pour changer de port, modifie port dans config.json.

Git refuse de travailler dans P:\pso-companion (« dubious ownership »)

Le disque P: n'enregistre pas les propriétaires de fichiers. Autorise le dossier une fois :

git config --global --add safe.directory P:/pso-companion

Glossaire

Preview (PVW)
L'image préparée, pas encore à l'antenne. Tally vert.
Program (PGM)
L'image diffusée. Tally rouge.
Transition
Passage de la preview au program : Cut (instantané), Fade (fondu)…
Stinger
Transition vidéo (animation plein écran) qui masque le changement d'image.
Overlay vMix
Calque vMix posé par-dessus l'image, numéroté de 1 à 8. À ne pas confondre avec les overlays PSO, qui sont des pages web dans OBS ou vMix.
FTB
Fade To Black : fondu au noir de la sortie.
Tally
Signal de couleur qui dit si une source est en preview ou à l'antenne.
Step
État d'une touche Companion. Une touche à 2 steps fait une chose au 1er appui et une autre au 2e.
Feedback
Règle Companion qui colore une touche selon l'état d'un logiciel.
Spec
Fichier JSON qui décrit les touches à fabriquer. Le script le transforme en fichier Companion.
Skill
Paquet d'instructions que Claude Code charge pour une tâche précise, ici companion.
