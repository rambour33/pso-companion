Le principe

Le Stream Deck ne sait rien faire tout seul. Chaque touche est configurée dans Companion, qui envoie un ordre au bon logiciel au moment où tu appuies.

Stream Deck XL32 touches (8 × 4). Une page = un jeu de 32 touches. ⬆️ ⬇️ changent de page.
CompanionContient la config des touches (le fichier .companionconfig) et deux connexions : http et vmix.
Serveur PSOAffiche / cache les overlays OBS, gère le score.HTTP GET → localhost:3002/api/deck/…
vMixPreview, program, transitions, stingers, overlays, REC, stream, replay, audio.TCP → 127.0.0.1:8099

Companion peut aussi lire l'état de vMix : une touche peut s'allumer en vert quand son input est en preview, en rouge quand il est à l'antenne, en rouge quand l'enregistrement tourne. C'est ce qu'on appelle un feedback.

Les fichiers

Tout est rangé à trois endroits. Le dépôt P:\pso-companion (aussi sur GitHub) est la version de référence, chaque skill y a son dossier dans skills\ ; le dossier .claude est la copie que Claude utilise ; le dossier PSO\companion contient les fichiers qu'on importe dans Companion.

Serveur de skills

Un petit serveur local, sur le même principe que PSO, met les skills et cette documentation à disposition de tous les PC de la régie.

AdresseContenu
http://<IP>:3010/Catalogue : chaque skill avec son .zip, sa commande d'installation et la lecture de ses fichiers. Liste aussi les exports Companion à télécharger.
http://<IP>:3010/docsCette documentation.
/download/skills/companion.zipLe skill companion, prêt à décompresser dans .claude\skills.
/api/skillsLa liste des skills en JSON.

Lancer le serveur

Double-clique sur P:\pso-companion\start.bat. Au premier lancement il installe ses dépendances, puis ouvre le catalogue. La fenêtre affiche les adresses à utiliser depuis les autres PC :

📦 pso-companion démarré !

  ── Ce PC (localhost) ──────────────────────────────────────
   Skills     → http://localhost:3010/
   Doc        → http://localhost:3010/docs

  ── Autre PC (réseau local) ────────────────────────────────
   Skills     → http://192.168.1.x:3010/

Ajouter un skill

Crée un dossier dans P:\pso-companion\skills\ avec un SKILL.md dont l'en-tête contient name: et description:. Il apparaît dans le catalogue au prochain rechargement de la page, sans redémarrer le serveur.

Le serveur est en lecture seule mais sans mot de passe : tout PC du réseau local peut télécharger les skills et les exports Companion. Ne le laisse pas tourner sur un réseau public.

Si Windows demande l'autorisation du pare-feu au premier lancement, autorise les réseaux privés, sinon les autres PC ne pourront pas l'ouvrir.

Mise en place

Coche chaque étape quand elle est faite. Ta progression reste enregistrée dans ce navigateur.

0 / 8

  1. Vérifier les logiciels

    • Companion 4.3 ou plus récent (tu as la 4.3.1). Le module vMix v5 en a besoin.
    • vMix ouvert sur le PC de régie. Le replay demande une édition qui l'inclut (4K ou Pro).
    • Python 3 : tape python --version dans un terminal.
    • Git et GitHub CLI si tu veux récupérer ou mettre à jour le dépôt.
    • Le serveur PSO se lance avec start.bat dans P:\PSO 2\PSO.

  2. Récupérer le dépôt

    Déjà fait sur ce PC : le dépôt est dans P:\pso-companion. Sur un autre PC :

    git clone https://github.com/rambour33/pso-companion.git P:\pso-companion

    Puis lance le serveur de skills avec P:\pso-companion\start.bat (voir la section Serveur de skills).

    Pour récupérer les dernières modifications plus tard :

    git -C P:\pso-companion pull

  3. Installer le skill pour Claude

    Déjà fait sur ce PC. Sur un autre PC, ou après une mise à jour du skill : ouvre le catalogue http://<IP>:3010/ et copie la commande d'installation du skill, ou tape directement (remplace l'IP) :

    Invoke-WebRequest http://192.168.1.x:3010/download/skills/companion.zip -OutFile "$env:TEMP\companion.zip"
Expand-Archive "$env:TEMP\companion.zip" -DestinationPath "P:\PSO 2\.claude\skills" -Force

    Sur le PC qui héberge le dépôt, tu peux aussi copier le dossier directement :

    Copy-Item P:\pso-companion\skills\companion "P:\PSO 2\.claude\skills\" -Recurse -Force

    Vérification : dans Claude Code ouvert sur P:\PSO 2, tape /companion. Le skill doit se charger.

  4. Préparer vMix

    Les automatisations de la page 4 appellent les inputs par leur nom. Renomme tes inputs dans vMix (clic droit sur l'input) pour qu'ils portent exactement ces noms :

    Nom exactContenu conseilléUtilisé par
    JEUCapture de la Switch / du jeuDébut match, Retour jeu
    CASTERSCaméra des commentateursCam casters
    PAUSEÉcran de pause / fondPause, Top 8
    MUSIQUEPlaylist ou musique d'attenteMute musique
    MICROSEntrée audio des microsMute micros
    • Stinger 1 : configure une vidéo de transition dans les réglages des stingers de vMix. Début match et Retour jeu l'utilisent.
    • Port : Companion parle à vMix sur le port TCP 8099. Le port du Web Controller de vMix ne doit pas être 8099.
    • Replay (optionnel) : ajoute un input Replay et lance son enregistrement pour que les touches replay fonctionnent.

  5. Générer le fichier Companion

    Le fichier PSO-Companion-vMix.companionconfig existe déjà : tu peux aussi le télécharger depuis le catalogue (section Exports Companion). Refais cette commande seulement si tu as modifié vmix-spec.json ou ton export d'origine :

    python P:\pso-companion\skills\companion\scripts\companion.py apply "P:\PSO 2\PSO\companion\PSO-Companion (19).companionconfig" P:\pso-companion\skills\companion\examples\vmix-spec.json --server "P:\PSO 2\PSO\server.js" --out "P:\PSO 2\PSO\companion\PSO-Companion-vMix.companionconfig"

    Pour contrôler le résultat, liste les touches du fichier :

    python P:\pso-companion\skills\companion\scripts\companion.py dump "P:\PSO 2\PSO\companion\PSO-Companion-vMix.companionconfig"
    vMix tourne sur un autre PC ? Change "vmix_host" au début de vmix-spec.json (par exemple "192.168.1.20") avant de générer, ou corrige l'adresse plus tard dans la connexion vmix de Companion.

  6. Importer dans Companion

    • Ouvre l'interface web de Companion, onglet Import / Export.
    • Importe PSO-Companion-vMix.companionconfig.
    • Companion propose de tout remplacer ou de choisir ce qu'on importe. Pour ne rien perdre de ce que tu as changé depuis, importe seulement les pages 3 et 4 et la connexion vmix.
    • Si Companion signale que le module studiocoast-vmix n'est pas installé, accepte son installation (version 5.0.5 ou plus récente).
    Companion ne relit pas le fichier tout seul. Chaque fois que le fichier est régénéré, il faut le réimporter.

  7. Vérifier les connexions

    • Onglet Connections : http et vmix doivent être au vert.
    • Sur le Stream Deck, page 4, la touche vMix CONNEXION passe du rouge au vert quand vMix répond.
    • Page 3, les touches PVW affichent le nom de tes inputs sous le numéro.

  8. Tester à blanc

    Avant un vrai stream, sans être en direct :

    • Page 3 : appuie sur PVW 1 (touche verte), puis CUT (elle devient rouge).
    • Page 3 : OVL 1 met l'input en preview dans l'overlay 1. OVL TOUT OFF l'enlève.
    • Page 4 : DÉBUT MATCH doit enchaîner écran VS (5 s), stinger vers JEU, puis scoreboard.
    • Ne teste pas GO LIVE ni FIN LIVE : ils lancent et coupent réellement le stream.

Preview (vMix) Program / actif Overlay PSO affiché Overlay PSO caché

Types de boutons

Chaque touche du deck appartient à l'une de ces familles. Le nom entre parenthèses est celui qu'on écrit dans une spec (le fichier qui décrit les touches).

Toggle overlay (toggle)

Deux états. 1er appui : l'overlay PSO s'affiche, la touche devient vert foncé. 2e appui : il se cache, la touche devient rouge.

Commande simple (get)

Un appui = un ordre au serveur PSO. Exemple : +1 au score du joueur 1.

Bouton maître (master)

Affiche ou cache tous les overlays d'une page d'un coup, recolore les autres touches et les remet dans le bon état.

Macro (macro)

Touche libre : actions vMix, ordres PSO et pauses, exécutés l'un après l'autre. C'est le type des pages 3 et 4.

Feedback

Couleur qui suit l'état réel de vMix : input en preview ou en direct, REC, stream, mute. Il se met à jour tout seul, même si tu agis dans vMix à la souris.

Enchaînement

Par défaut Companion lance toutes les actions d'une touche en même temps. Les macros les rangent dans un groupe séquentiel pour que les pauses (wait) soient respectées.

Créer ou modifier des boutons

Avec Claude (le plus simple)

Dans Claude Code ouvert sur P:\PSO 2, décris ce que tu veux en français. Le skill companion se charge tout seul. Exemples :

  • Ajoute sur la page 4 un bouton qui lance le stinger 2 puis affiche les casters.
  • Mets les inputs 9 à 16 en preview sur une nouvelle page 5.
  • Crée un bouton « Interview » : fondu vers l'input INTERVIEW, cache le scoreboard, mute la musique.
  • Change FADE 500 ms en FADE 1 s.

Claude modifie la spec, régénère le fichier, vérifie le résultat et te dit quoi réimporter.

À la main

Ouvre P:\pso-companion\skills\companion\examples\vmix-spec.json dans un éditeur, modifie ou ajoute une entrée, puis refais l'étape 5 du tutoriel. Une touche s'écrit ainsi :

{ "loc": "4/2/5", "kind": "macro", "text": "STINGER 2\nCASTERS", "bg": "#5a2d82",
  "actions": [
    { "get": "/api/deck/scoreboard/hide" },
    { "vmix": "previewInput", "input": "CASTERS" },
    { "vmix": "transition", "functionID": "Stinger2", "mix": 1 },
    { "wait": 1000 },
    { "get": "/api/deck/casters/show" }
  ],
  "feedbacks": [ { "vmix": "inputLive", "input": "CASTERS", "bg": "#CC0000" } ] }
ChampSignification
locEmplacement page/ligne/colonne. Lignes 0 à 3, colonnes 0 à 7. 4/2/5 = page 4, 3e ligne, 6e touche.
textTexte de la touche. \n = retour à la ligne. $(vmix:input_1_name) affiche le nom de l'input 1.

Dépannage

Une touche vMix ne fait rien
  • Regarde la touche vMix CONNEXION (page 4) : rouge = Companion ne joint pas vMix. Vérifie que vMix est ouvert, l'adresse de la connexion vmix et le port 8099.
  • Si la touche utilise un nom d'input (JEU, PAUSE…), vérifie que l'input porte exactement ce nom dans vMix.
  • Les touches stinger demandent un stinger configuré dans vMix.
Une touche PSO ne fait rien
  • Le serveur PSO doit tourner (start.bat). Test rapide : ouvre http://localhost:3002/api/deck dans un navigateur.
  • Les touches Éléments SB, Scène 1 à 9, All Scènes et Super Scènes appellent des overlays absents de la liste TRANSITION_IDS du server.js actuel. Le serveur répond « introuvable ». Il faut ajouter ces overlays au serveur pour qu'elles fonctionnent.
Les touches TW Chat, TW Viewer et YT Chat n'apparaissent pas

Dans ton export, elles sont rangées en ligne 4 de la page 1, alors que le Stream Deck XL n'a que 4 lignes (0 à 3). Déplace-les dans Companion vers des cases libres de la ligne 3 (colonnes 3 à 7).

Les pauses d'un enchaînement ne sont pas respectées

Les actions doivent être dans un groupe séquentiel. Avec une macro générée par le script c'est automatique ("sequential": true par défaut). Si tu as recréé la touche à la main dans Companion, place les actions dans un Action Group en mode Sequential.

J'ai modifié la spec mais le Stream Deck n'a pas changé

Il faut régénérer le fichier (étape 5) puis le réimporter dans Companion (étape 6). Companion ne surveille pas le fichier.

Les touches PVW n'affichent pas le nom des inputs

La connexion vMix doit s'appeler exactement vmix dans Companion : c'est ce nom qui apparaît dans $(vmix:input_1_name). Si tu la renommes, les textes affichent la variable brute.

Git refuse de travailler dans P:\pso-companion (« dubious ownership »)

Le disque P: n'enregistre pas les propriétaires de fichiers. Autorise le dossier une fois :

git config --global --add safe.directory P:/pso-companion

Glossaire

Preview (PVW)
L'image préparée, pas encore à l'antenne. Tally vert.
Program (PGM)
L'image diffusée. Tally rouge.
Transition
Passage de la preview au program : Cut (instantané), Fade (fondu)…
Stinger
Transition vidéo (animation plein écran) qui masque le changement d'image.
Overlay vMix
Calque vMix posé par-dessus l'image, numéroté de 1 à 8. À ne pas confondre avec les overlays PSO, qui sont des pages web dans OBS ou vMix.
FTB
Fade To Black : fondu au noir de la sortie.
Tally
Signal de couleur qui dit si une source est en preview ou à l'antenne.
Step
État d'une touche Companion. Une touche à 2 steps fait une chose au 1er appui et une autre au 2e.
Feedback
Règle Companion qui colore une touche selon l'état d'un logiciel.
Spec
Fichier JSON qui décrit les touches à fabriquer. Le script le transforme en fichier Companion.
Skill
Paquet d'instructions que Claude Code charge pour une tâche précise, ici companion.
